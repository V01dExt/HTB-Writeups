Lame Machine — HTB Writeup

Introduction

Welcome to the first of many writeups for HTB labs that I’ll be doing! This is the first machine that I’ve done and it is a great first machine for anyone that is in the beginning of their red teaming journey. Lame is a retired machine that focuses on using Nmap and the Metasploit Framework to enumerate and exploit the target and obtain the user and root flags. It also only requires one exploit to find both of the flags. Let’s get right into this machine!

Initial Enumeration

As always, I’ll start off with an Nmap scan.

nmap -A -p- -v -sCV <TARGET IP>

Whenever I start up a lab, I always start off with an Nmap scan to see what I am working with. I get a solid understanding of what ports are open, what services are running, and their versions so that I can try and exploit them. I use the -A tag for an aggressive scan to get results fast, the -p- tag to scan all 65,535 ports so I don’t miss any non-standard ports, -v for a better description output during the scan, and -sCV to get active TCP connections and the versions of whatever services are running. Let’s look at the results.

The first thing I noticed after the scan is that FTP is open and running on port 21. I was also given vsftpd v2.3.4 as the service and version number of the server. This is definitely something that I will look into to see if there are any publicly known exploits that I can use. For now, I’m going to look through the rest of the results to see what else was found.

At the bottom of the results, I was also given the Samba service and version number of 3.0.20. This is also very interesting and after seeing both of these results; I will now do some research to see what I can find on both of these two.

Researching the Findings

I started with looking for what the vsftpd version might hold. What I found was a popular backdoor exploit that grants the attacker root level access to the server named CVE-2011–2523. It starts with the user sending a username ending with a :). For example: user:). That is what activates the backdoor. This triggers the vsf_sysutil_extra function to spawn a bind shell that actively listens on port 6200 for any connections. the functions vsf_sysutil_bind and vsf_sysutil_accept then establish the shell listener connection with root privileges. There is no password required and no authorization or authentication. This seems like a great option to try but I will look into the samba version and then decide from there.

I also found a very good-looking vulnerability for samba that was named CVE-2007–2447. This lies within the MS-RPC functions of the samba server. It is a remote command injection exploit specifically found in an option in the smb.conf file. It starts with the username map script option being enabled. This option passes the username as a command line argument. The SamrChangePassword function runs pre-authentication, so an attacker can pass a username that contains shell metacharacters and malicious input due to no input sanitization. All commands can pass directly through /bin/sh and be executed. This exploit also creates a root shell for the attacker to use that grants them full access to the system.

Gaining a Foothold and Exploitation

Now that I have done all of the research I need. It’s time to launch my attack against the target. I decided to go with attacking the samba service, so I will launch Metasploit to search for the exploit I found during my research. Both of these vulnerabilities are in the framework and available to use.

msfconsole
search samba 3.0.20

After searching samba 3.0.20, I found the exploit. It’s very straight-forward from here so I’ll select it and look at my options for configuration.

use 0
show options

All I have to do is set my RHOSTS, which is the target I’m running the exploit on, and my LHOST, which is my own IP address.

set RHOSTS <TARGET IP>
set LHOST <YOUR IP>

Now all that is left to do now is type run to launch the exploit and gain the root shell.

run
whoami

Now that I ran the exploit, I check where I landed using whoami and as expected, I landed as root. All there is to do now is move around and find the user and root flag!

Finding the Flags

Finding both of these flags is fairly easy. I’ll look for the user flag first. I’ll check which directory I’m in, then I’ll maneuver accordingly.

pwd
cd home
ls
cd makis
ls

Just like that, I found the user.txt flag! Now I can open the contents using the cat command and submit the flag. I’m not done yet though! I still have to retrieve the flag in the root directory.

cd root
ls

All it took was a couple more commands to find the root.txt file flag! Now I can go ahead and submit the contents and complete the lab. I hope everyone that does this lab finds it as fun as I did! I also hope that anyone reading this found my writeup very helpful if you were stuck on what to do like I was at first. Labs are very intimidating at first but once you do more and develop your own methodology for hacking, it all becomes easier over time. If you were following along on your own machine, congratulations on finding the flags!

Debrief

As one can see, the Lame machine is great for beginners. It helped me apply the basic tools that red teamers use everyday like Nmap and Metasploit. I’ll say this as I have heard it time and time again, don’t rely on using Metasploit for everything. It is a very powerful tool and you can definitely see why many penetration testing certifications have strict rules on using it in exams. It is important to understand what is happening when you run an exploit. Metasploit won’t work 100% of the time and you don’t want to be stumped the minute that you have to manually hack. Even in this lab, if you try to use the vsftpd exploit, it won’t work and you have to run the samba exploit anyways. I recommend learning how exploits work and manually practice them before jumping right into spamming Metasploit. I’ll even challenge you to exploit this machine manually and do the exploits without using Metasploit or any other automation tools. It seems like a lot at first but keep going at it and studying a little bit everyday and hacking will feel like second nature. With all that said, I hope everyone enjoyed this writeup and even learned a thing or two from it! Happy hacking everyone!
