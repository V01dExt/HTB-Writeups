Knife Machine — HTB Writeup

Introduction:

Welcome to this writeup for the easy, retired Linux machine dubbed Knife in HTB. This one is fairly simple. All you need is just a little bit of OSINT paired with some scanning and automated scripts to get the user and root flags. These easy machines mainly focus on basic enumeration to uncover a public vulnerability with plenty of available tools and exploits to easily pwn these. So let’s get right into this one!

Initial Enumeration:

As I always do with every machine, I’ll start off with an Nmap scan.

nmap -sCV -A -p- -v 10.129.16.158

I use all of these tags to get as much information as possible on the target and to see every little detail that the scan is doing. I search for every open port and look for every active connection to see what I have available for me to research. Let’s look at what I found.

I didn’t find much. I only found the usual ports open, that being port 22 and port 80. For now, let’s visit the webpage and do some digging.

Once again, I am still not finding a lot to work with. There are no pages or links to click on. I decide to use burp suite to analyze the request and response headers to see if I can get more information about what is running the web page.

Now I have something! After intercepting the response with the proxy and sending it to the repeater for analysis, we get the Server version and the X-Powered-By version in the response header so now we can do some research to see what potential exploits and vulnerabilities there are.

Researching the Findings:

All it took was one search of the PHP version number to find a backdoor vulnerability that leads to a remote code execution exploit. It works by exploiting the hidden backdoor in the source code that executes PHP code in the User-Agent header as long as the string starts with zerodium. All it is is adding an extra t at the end so its “User-Agentt:”, then ‘zerodiumsystem(“enter any command”)’.

For example:

User-Agentt: zerodiumsystem("pwd")

I also found a Github repository with two scripts, one that leverages the backdoor to gain a pseudo system shell and another one that gains a reverse shell on the target.

It can be found at https://github.com/flast101/php-8.1.0-dev-backdoor-rce. Now that I have all I need, It is time for me to use this exploit to retrieve the flags.

Exploitation:

The first thing that I do is run the backdoor exploit to see if that will get me access to get the user flag. So I go ahead and download the repo.

git clone http://github.com/flast101/php-8.1.0-devbackdoor-rce.git
cd php-8.1.0-dev-backdoor-rce
ls
python3 backdoor_php_8.1.0-dev.py

As you can see, It’s a very easy exploit to run. All I had to do was type in the url and I gained a shell as the james user. The flags are always in the user home directory so I just go ahead and open it to get the flag.

cat /home/james/user.txt

Just like that, I got the user flag. Now I got to see what my privileges are to see if I can access the root directory to get the flag.

sudo -l

It seems like I am only able to run the knife command as root. The command deals with executing OS commands so I’ll try it and see if it works.

sudo knife exec -E 'system("ls")'

Looks like I had zero luck with that, but let’s see if running the reverse shell script from the repo works. For reference, reverse shells are a post-exploitation technique where an already compromised system initiates an outbound connection with the attacker’s machine. The attacker machine acts as a server and listens for incoming connections. the victim machine acts as a client executing the payload that connects to the attacker’s IP and port. After the connection gets established, the attacker has an command line shell on the victim’s machine. This allows full control to deploy malware, pivot to other systems, and execute commands. A reverse shell is much more favorable to a bind shell because firewalls typically allow outbound traffic and blocks incoming traffic, allowing attackers to bypass security that would otherwise block a bind shell connection.

This script is also really simple to run. All I need to specify is the target, my own IP, and my own port. Then, I start my listener in another terminal to connect as the James user again and run the knife command to use root privileges to get the root flag.

Yet again, another machine pwned. A pretty simple machine and a great one if you’re just starting out in learning ethical hacking and its methodologies.

Debrief:

I hope everyone enjoyed this writeup for the Knife machine! It is definitely a fun one to do no matter your experience level. OSINT and doing your research are very vital skills to learn especially if you’re a beginner. This goes to show everyone as well that hacking won’t have you in the terminal saying you hacked the mainframe like they do in the movies. There is a lot of researching, a lot of googling, and it teaches that you won’t know everything or what you can do when you think that you’ve found something. It’s okay to not know everything that you see when you’re doing labs or bug bounties as you try and start you career as a Penetration Tester a Bug Bounty Hunter. As long as you’re attempting to learn and continue to apply your knowledge, It will become easier over time. I will definitely be posting more machines and attempting ones that have a higher difficulty so that I am always challenging myself. With all that said, I hope you all learned something interesting from this writeup or used it to help you if you’re also doing this machine!
