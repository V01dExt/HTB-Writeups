Active — HTB Writeup

Introduction:

Welcome to the third lab that I’ve completed in my AD mini-series. If you had a chance to read the last one, then you’ll know that this is the final easy difficulty one before I move on to the medium difficulty. This lab involves using smbmap to find encrypted credentials and then kerberoasting the Administrator hash to escalate your privileges. It is another quick beginner AD machine that I highly recommend to anyone else started out in HackTheBox, especially if you’re new to enumerating and attacking Active Directory. This lab didn’t have too many steps, so I’ll get right into this one.

Enumeration:

First things first, an nmap scan.

nmap -sCV -A -p- -v <TARGET IP>

Like many AD labs, there is always a ton of results.

We have ldap, dns, and maybe even smb open. Plus a ton of other random ports that are open. I don’t need to worry about them though. The past couple labs I did, I started with ldapsearch. In this one however, I wasn’t allowed to anonymously bind. I decided to see if I could enumerate through smb.

smbmap -H <TARGET IP>

I’ll see if I can read or write anything anonymously. There wasn’t much that I had any sort of access too except for the Replication share. I was allowed to read it. So I figured I would look through that share.

smbmap -H <TARGET IP> -R 'Replication'

I was a bit surprised by all of the information I was able to get from this. This is the hardest part for me: looking through and seeing which one of these has anything that will help me. It took me a while if I am being honest. At first, I looked through DsfrPrivate and those specific shares and directories. Nothing came out of it, so I decided to just take my time and look through all of them since I couldn’t figure out which one would have what I needed just by looking at the names. Luckily for me, I did stumble across what I needed when I went into Groups.

Gaining a Foothold:

smbmap -H <TARGET IP> -R 'Replication\active.htb\Policies\{31B2F340-016D-11D2-945F-00C04FB984F9}\MACHINE\Preferences\'

I found an xml file that seemed promising. So I went ahead and downloaded it to my host machine.

smbmap -H <TARGET IP> --download 'Replication\active.htb\Policies\{31B2F340-016D-11D2-945F-00C04FB984F9}\MACHINE\Preferences\Groups\Groups.xml'

Then, I read the contents of the file.

cat <TARGET IP>-Replication_active.htb_Policies_{31B2F340-016D-11D2-945F-00C04FB984F9}_MACHINE_Preferences_Groups_Groups.xml

I got something good. I got an encrypted password! At first, I wasn’t sure if it was a hash or something else. After I did some research, I found out that it was a AES-256 encrypted password. I also found a couple tools that can decrypt it for me. The regular gpp-decrypt tool did not want to install on my machine, but I was able to get the python version of it which worked just fine.

pip3 install gpp-cpass-decrypt

This is how you install it, in case you decide to use this tool in the lab or in the future when you come across AES-256 encryption again. The syntax is fairly simple as well.

gpp_cpass_decrypt -c edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfcUNH8pG5aSVYdYw/NglVmQ

It is just one command with the encrypted password that I got and it successfully returned the plaintext password of GPPstillStandingStrong2k18 for the SVC_TGS user. Now I can go back and use smbclient and access the Users share to read the user flag.

smbclient -U SVC$GPPstillStandingStrong2k10 //<TARGET IP>/Users
dir
cd SVC_TGS
cd Desktop
dir
get user.txt

I was able to successfully authenticate myself and download the user.txt file to my host machine to read.

cat user.txt

This one wasn’t that bad to get besides when I struggled to see which file had contents that I needed. I’ve learned recently that it trips me up the most and I’ll get frustrated if I am looking forever and finding nothing. Nevertheless, I got the flag and now I have to find a way to escalate my privileges.

Privilege Escalation:

Since I have credentials in the domain, I can most likely use ldapsearch to find any misconfigurations or vulnerabilities. Like I always do, I’ll use one of my cheatsheet commands so that I can quickly copy and paste what I need. This helps me out so much, especially when it comes to powershell or ldap queries just because they are so long to type out and I haven’t gotten to the point of memorizing what the strings of numbers and letters are just by typing them out. I’ll see if there are any kerberoastable accounts within this domain first.

ldapsearch -H ldap://<TARGET IP> -D "SVC_TGS@active.htb" -w "GPPstillStandingStrong2k18" -b "DC=active,DC=htb" "(objectClass=user)(servicePrincipalName=*)(!(cn=krbtgt))(!(samaccounttype=805306369)))"

This query returns all users that are kerberoastable. It works by returning all user objects with an SPN registered, but excludes krbtgt and computer accounts. It tells us that the Administrator hash is kerberoastable, so I’ll waste no time and get right on it to get that hash and password.

GetUserSPNs.py -request -dc-ip <TARGET IP> active.htb/SVC_TGS:GPPstillStandingStrong2k18 -request-user Administrator

I used the GetUserSPNs.py tool from the Impacket suite to get the hash of the Administrator. I could’ve probably skipped the ldapsearch step and just use this tool but I am trying to make sure that I enumerate more carefully and truly understand what I am doing. Now that I have the hash, I should be able to crack it offline with hashcat and get the password.

hashcat -m 13100 hash.txt /usr/share/wordlists/rockyou.txt

I put the hash into a file and use the rockyou.txt list to brute force the password out of the hash. Hashcat has easily become one of my favorite tools as of recently.

Yet again, I was able to crack the hash and get the password as Ticketmaster1968. Now that I have the username and password of a privileged user, I can authenticate with the credentials and hopefully get that root flag. I’ll use another Impacket tool called wmiexec.py to gain a session. Unlike the last two labs, I was unable to use evil-winrm in this lab.

wmiexec.py active.htb/Administrator:Ticketmaster1968@<TARGET IP>
cd \Users\Administrator\Desktop
dir
type root.txt

Another root flag gained! I enjoyed this one a lot but now I feel ready to attack harder labs with complex attack paths, more steps, and even cooler exploits.
